# フォークの申請

Org の中にフォークを作る申請を受け、管理者の承認の後に自動で作る仕組みの検証用のリポジトリ。

## 流れ

1. 「Issues」→「New issue」→「フォークの申請」の様式で申請する
2. ワークフロー「フォークの申請の処理」が、申請者がこの Org のメンバーか（App の権限で Org に問い合わせる）と書式を確かめる。合わなければ Issue に理由を書いて閉じる
3. Environment「fork-approval」の承認者が、実行の画面で申請を読んで承認する
4. App「kikuchi-fork-bot」の権限で、次を順に行う
   - フォーク元が非公開なら、フォーク元のフォークを有効にする
   - Org の中にフォークを作る（既定のブランチだけを写す）
   - フォーク元のフォークを無効に戻す（失敗しても戻す）
   - 申請のチームに書き込みの権限、申請者に申請の権限を付ける
5. 結果を Issue に書いて閉じる

## 前提の設定

| 置き場 | 名前 | 中身 |
|---|---|---|
| リポジトリの変数 | APP_ID | App の番号 |
| リポジトリの秘密情報 | APP_PRIVATE_KEY | App の秘密鍵 |
| Environment | fork-approval | 承認者を付ける |
| ラベル | fork-request | 様式が申請に付けるラベル |

App に要る権限は、リポジトリの管理（書き込み）・中身（読み取り）・Issue（書き込み）・Org のメンバー（書き込み）。

## まだ扱っていないこと

- Org の段のフォークの許可の切り替え。App に Org の管理の権限が要るため、今は扱っていない
- 期限の切れたフォークの知らせ、メンバーの追加・同期の申請
